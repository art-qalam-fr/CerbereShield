# ============================================================================
# doh_bypass.txt — Liste curée de résolveurs DNS-over-HTTPS (DoH) publics
# ============================================================================
# Projet : Cerbere Security Shield — module parental_control (contrôle domestique)
#
# But : empêcher qu'un navigateur (Firefox, Chrome, Edge…) ou une application
#       contourne le filtrage DNS local en interrogeant un résolveur DoH
#       public (RFC 8484) — les requêtes passent en HTTPS/443 et échappent au
#       DNS filtrant de la box / du Shield.
#
# Provenance : liste curée MANUELLEMENT pour le projet, hostnames vérifiés sur
#              les listes publiques de résolveurs DoH (wiki curl
#              « DNS over HTTPS », flo-wer/doh-list) et les documentations
#              officielles des fournisseurs (Google, Cloudflare, Quad9,
#              OpenDNS, NextDNS, AdGuard, Mullvad, dns.sb…).
#              AUCUNE liste externe n'est importée — pas de licence tierce,
#              contenu 100 % projet, versionné dans le dépôt.
# Dernière mise à jour : 2026-09-21
#
# ⚠ LIMITATION — bloquer ces domaines LIMITE le contournement DoH sans
#   l'ÉLIMINER : un résolveur DoH auto-hébergé, joignable directement par IP
#   littérale (https://1.1.1.1/dns-query), ou relayé via un CDN / fonction
#   serverless reste possible ; DoT (853) et DoQ (QUIC) empruntent d'autres
#   canaux non couverts par cette liste de domaines.
#
# ⚠ RAPPEL — le blocage DNS est BINAIRE :
#   chaque entrée bloque le domaine ET tous ses sous-domaines (matching par
#   suffixe).
#
# Format : un domaine par ligne (minuscules, sans schéma ni chemin).
#          Lignes vides et commentaires (#) ignorés par le chargeur.
# ============================================================================

# CAS PARTICULIERS DOCUMENTÉS
# ----------------------------------------------------------------------------
# - use-application-dns.net : domaine « canary » utilisé par Firefox pour
#   détecter la volonté du réseau — NE PAS le bloquer : une réponse NXDOMAIN
#   ordonne au navigateur de DÉSACTIVER DoH et de revenir au DNS système
#   filtré, ce qui est exactement le comportement recherché ici.
# - Control D, CleanBrowsing et DNS4EU choisissent leur politique de filtrage
#   par le CHEMIN de l'URL (/p0, /doh/family-filter/, …) : le matching par
#   suffixe sur le domaine bloque toutes les variantes d'un coup.
# - Plusieurs résolveurs acceptent une IP littérale comme URL DoH
#   (https://1.1.1.1/, https://9.9.9.9/…) : hors portée du blocage de
#   domaine — compléter par le blocage IP si le moteur le permet.
